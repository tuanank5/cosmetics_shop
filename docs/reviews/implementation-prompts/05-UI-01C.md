# UI-01C · Details/password/notice

## Cập nhật sau AUTH-02

Tái dùng form mật khẩu, vùng lỗi, xác nhận Admin, focus, nhãn quản lý tài khoản. Test cả no-JS, zoom và mobile. Kiểm zoom, bàn phím, JS tắt và form xác nhận ở admin/user/detail. [Nghiệm thu AUTH-02](../AUTH-02-nghiem-thu-xac-thuc.md)

Khi owner giao prompt này, hãy thực hiện duy nhất UI-01C, Phase 3, và dừng sau checkpoint G5. BeautyShop là monolith Java 21, Spring MVC, Thymeleaf, JPA/JDBC, MariaDB và MongoDB cho nội dung review. Controller nhận HTTP/form, service giữ nghiệp vụ/transaction, repository đọc và ghi dữ liệu.

## Mục tiêu và quyết định

Native summary + CSS/fragment theo loại, password có ô điều khiển ổn định, vùng notice dùng chung Không nhúng handler inline; giữ form names, Authentication, Validation.

Giữ các quyết định owner mới nhất. Bảng review MariaDB cũ chỉ lưu lịch sử; không xóa, đồng bộ, ghi kép hoặc chuyển sang Mongo. Giữ quy tắc giá/ảnh SKU hiện tại. Phạm vi thanh toán Admin là trạng thái hiệu lực như chi tiết. Nhãn màn quản lý cả Customer và Admin là “Quản lý tài khoản” (UI-01C phụ trách); giữ các vai trò hiện tại.

## Phạm vi và trình tự thực hiện

File/class được xem xét: fragments/ui/header/admin-nav, auth/login/register, product/list/detail, admin/dashboard; app.js, components.css/admin.css/storefront.css. Kiểm tra đường dẫn hiện hành bằng rg; đặc biệt sau ARCH-01 dùng package trên HEAD. Biên dùng chung: Hợp đồng stable id, native open, CSS password, vùng notice, Chart.js và breakpoint. Chỉ sửa caller, test và tài liệu trực tiếp cần cho gói; ghi lý do đối với mỗi file ngoài danh mục dự kiến.

1. Kiểm kê component dùng ở chi tiết PDP, đơn Customer/Admin, returns, checkout/địa chỉ, trang SKU/catalog/voucher hiện hữu. Đối chiếu tiêu đề, breadcrumb/Quay lại G4, action, badge, empty/error, focus, table/overflow, font/spacing. Sửa sai khác cụ thể bằng fragments/ui, tokens.css và CSS có sẵn. Lập bảng màn đã sửa/giữ kèm lý do; muốn redesign toàn trang phải xin duyệt.
2. Cho catalog/filter qua GET giữ open theo tham số UI allowlist hoặc lọc active, sort/pager giữ ý định. PDP theo slug+id và entry Back, menu mobile/sidebar/discovery chỉ sống trong lần mở, chart-table có mặc định accessible, dialog không auto-reopen. Giữ native summary keyboard/no-JS, không tạo localStorage toàn site.
3. Đo rect trước/sau JS init và click password ở login/register, zoom 200%, mobile. Dùng fragment password có slot nút ổn định, minmax input, nhãn truy cập và focus, giữ BindingResult/name/autocomplete. Chuẩn bị vùng alert cho G7/G11 mà không consume message ở component.
4. Kiểm NguoiDung_Repository và AdminNguoiDung_Controller: nếu /admin/users quản lý cả Customer và Admin, đổi chính xác nhãn điều hướng và tiêu đề quản lý liên quan thành “Quản lý tài khoản”. Không đổi tập query, count, route, quyền, chống tự khóa, hay mọi chữ Khách hàng trong nội dung nghiệp vụ khác. Kiểm aria-current, desktop/mobile và nhãn trang con.

## Bất biến và giới hạn

Giữ form session, quyền backend theo vai trò/chủ sở hữu, CSRF, validation, transaction/locking, snapshot, idempotency, State Machine và định nghĩa P20. Với dữ liệu giao dịch đọc hợp đồng docs/design/03-order-payment-inventory.md. Chỉ TK-04 thêm chi tiết khi gộp vượt tồn dương. Không thêm dependency, migration, sửa migration cũ, thay schema hay mở rộng tính năng ngoài gói. Không hard-delete danh mục/hãng như một giải pháp. Gác SHOP-12, AI/RAG/Ollama, phân quyền con, cache/index mới và redesign diện rộng. Không đưa secrets/PII vào URL, log, ảnh QA hoặc storage.

## Kiểm thử, nghiệm thu và quay lui

- Thiết lập fixture mô tả ở các bước trên. Tạo/cập nhật test cho nhánh thành công, lỗi và biên vừa đổi; giữ test nghiệp vụ cũ còn hiệu lực. Regression gate: **G5 keyboard, zoom, no-JS, login/register và Admin dashboard**.
- Dùng JDK 21, chạy `mvn -o test` và `mvn -o -DskipTests package` khi đổi code. Theo profile liên quan chạy tích hợp MariaDB/Mongo bằng database trống riêng, ghi môi trường và số chạy/skip/lỗi. Không chạy seed hoặc restore lên DB owner. Thiếu môi trường phải ghi rõ gate nào còn hở. Với UI kiểm keyboard, no-JS và responsive. Owner tự nhập tài khoản nếu cần.
- Chỉ nghiệm thu khi: **Password rect ổn, summary độc lập, mobile menu và chart tables đọc được**. Báo kết quả quan sát riêng với nhận định từ mã.
- Rủi ro và phương án quay lui: CSS chung có thể đổi header/Chart.js; rollback component riêng, giữ HTML native. Đây là phương án trình owner khi cần; bảo toàn dữ liệu, không dùng lệnh phá hủy hoặc tự đảo thay đổi của gói khác.
